# 寸镜 / PierceView 1.0 兼容性说明

## 支持范围

寸镜依赖 Windows 桌面窗口管理器（DWM）的窗口缩略图和 Win32 窗口 region。以下普通窗口通常兼容较好：

- 传统 Win32、WinForms、WPF 应用。
- 常规浏览器页面，包括普通 Chromium/Edge/Chrome 页面。
- 常规 Electron 桌面应用。
- 未最小化、未被系统 cloaked、与寸镜权限等级相同的顶层窗口。

“通常兼容”不是全量保证；同一应用的登录页、视频页、GPU 画布和普通文本页可能使用不同渲染路径。

## 1.0 层级规则

每次按下 F8 时，寸镜只选择圆心位置紧贴宿主后的一个来源窗口。来源在本次按键会话中固定：

- 不同时合成多个窗口。
- 不继续识别 -2、-3 或 -4。
- 不因移动或点击切换来源。
- 来源窗口没有覆盖到的区域，不承诺显示更深层内容。

## 可能只有点击、没有画面的类型

| 类型 | 简单例子 | 原因 |
|---|---|---|
| 无重定向窗口 | 开发者显式使用 `WS_EX_NOREDIRECTIONBITMAP` 的窗口；部分 DirectComposition 自绘壳、桌面小组件或录屏叠加层 | DWM 没有可供 thumbnail 读取的常规重定向位图 |
| 受保护视频 | 浏览器中的 DRM/HDCP 视频、受保护媒体播放器画面 | 系统有意禁止复制受保护表面 |
| GPU 独立表面 | 某些硬件 overlay、DirectX/Vulkan 自绘视图、独占全屏内容 | 画面未进入普通 DWM thumbnail 路径 |
| 游戏与反作弊客户端 | League of Legends/Riot Client/Vanguard；使用 EAC、BattlEye、FACEIT 的游戏 | 渲染或安全策略可能阻止捕获，也可能把窗口操作工具视为不兼容 |
| 系统安全界面 | UAC 安全桌面、锁屏、部分系统 Shell 界面 | 会话、桌面或权限隔离 |
| 最小化/隐藏窗口 | 最小化应用、其他虚拟桌面的 cloaked 窗口 | DWM 可能暂停或替换其可复制表面 |
| 权限更高的窗口 | 以管理员运行的工具或系统管理界面，而寸镜为普通权限 | UIPI/权限边界可能拒绝 region、样式或 Z-order 操作 |

“无重定向窗口”是窗口实现方式，不是固定应用名单；应用升级后也可能改变，因此寸镜不按品牌武断判定。

## 游戏说明

风险不只涉及网游。单机游戏也可能带 EAC/BattlEye 等反作弊，游戏启动器和客户端本身也可能使用受保护或特殊 GPU 界面。寸镜 1.0 不尝试判断游戏是否安全，也不绕过任何保护。

统一规则：启动游戏、游戏启动器或反作弊服务前，从托盘完全退出寸镜，而不是只暂停或松开 F8。

跨应用拖放同样属于兼容能力：源应用必须允许开始 OLE/HTML5 拖放，目标应用必须接受相应数据格式，且两边权限等级应一致。某些浏览器图片、受保护内容或管理员窗口不会允许拖出或拖入，这不代表透视本身失效。

## 常见现象与判断

- 圆内为纯色、黑色，但点击有效：物理 region 已成功，DWM 视觉来源不可复制。
- 只有来源窗口覆盖区域可见：符合 1.0 单层限制。
- 圆不出现：宿主可能是 Shell/安全窗口、权限不匹配，或无法修改 region。
- 点击后来源短暂闪动：来源主动争夺前台，守卫正在恢复宿主层级。
- 来源最小化后画面停止：DWM 不再提供稳定实时表面。

遇到问题时，先在记事本、文件资源管理器或普通浏览器页面之间验证；若基础窗口正常而特定应用失败，应按该应用不兼容处理，不要尝试关闭其安全机制。
