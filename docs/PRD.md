# QL eye 产品需求文档（PRD）

- 文档版本：0.7
- 产品版本：0.7.1 技术预览
- 负责人：QL eye Project
- 状态：开发与验证中

## 1. 产品概述

QL eye 是 Windows 桌面局部窗口透视与交互工具，当前可执行模块名为 `WindowPortal.exe`。用户按住 F8 时，在当前前台应用内创建一个跟随鼠标的圆形区域；区域内按真实 Z-order 同时显示最多三个后台应用的可见部分，并允许鼠标操作命中的后台应用。被点击的后台应用只能提升到宿主应用正下方，宿主始终保持前台。

## 2. 问题陈述

多窗口用户为了查看或操作后台资料，通常必须 Alt+Tab、调整窗口、使用分屏或创建固定 PiP。这些操作会打断当前上下文。现有透明度工具通常让整个窗口变透明，现有局部预览工具通常只复制单个窗口，并不能按真实桌面空间同时显示多层后台应用。

## 3. 目标与非目标

### 3.1 目标

- 按住快捷键即可临时查看当前应用之后的真实桌面层级。
- 移动时只出现一个与鼠标同步的圆，不产生双圆、撕裂或持续黑帧。
- 圆中同时合成 -1、-2、-3 的可见区域。
- 真实鼠标点击、拖动和滚轮送达目标窗口。
- 点击深层窗口时，保持宿主前台，只重新排列宿主之后的窗口。
- 提供清晰的兼容性诊断、安全边界和可恢复性。

### 3.2 非目标

- 不绕过 DRM、反作弊、UAC 安全桌面或系统访问控制。
- 不注入 DLL、不读取/写入其他进程内存、不模拟键盘输入。
- 不保证独占全屏游戏、受保护视频或无 DWM 重定向表面的画面可见。
- 0.7 不提供跨平台、云同步、账号体系或商业支付。

## 4. 目标用户与场景

1. AI/IDE 用户：主窗口保持 Codex、ChatGPT、IDE，临时查看浏览器或文件管理器。
2. 内容创作者：不改变编辑器布局，短时参考素材或监控面板。
3. 多窗口办公用户：在表格、文档和网页间快速核对信息。
4. 可访问性场景：减少频繁 Alt+Tab，但不替代系统辅助技术。

## 5. 功能需求

| ID | 优先级 | 需求 | 验收标准 |
|---|---:|---|---|
| FR-001 | P0 | 按住 F8 启用圆形透视，松开恢复 | 正常、Esc、Ctrl+C、进程正常退出路径均恢复窗口 region 与扩展样式 |
| FR-002 | P0 | 圆跟随鼠标 | 所有视觉图层位置一致；自动测试任一采样时刻最多一个不同圆位置 |
| FR-003 | P0 | 同时合成三层 | 构造红色 -1、绿色 -2、蓝色 -3 后，圆内三个非重叠采样点均得到对应颜色 |
| FR-004 | P0 | 受限 Z-order 提升 | 点击 -2 后顺序为“宿主 → 原 -2 → 原 -1”，宿主前台 HWND 不变 |
| FR-005 | P0 | 真实鼠标交互 | 后台控件收到 Click；拖动、滚轮不使用合成输入 |
| FR-006 | P0 | 安全排除 | League/Riot/Vanguard、EAC、BattlEye、FACEIT 等默认禁止视觉注册和窗口修改 |
| FR-007 | P0 | 兼容性报告 | `--compatibility-report` 只读输出每个窗口的视觉/交互结论与原因 |
| FR-008 | P1 | 动态层级变化 | 点击、移动或窗口变化后，下一帧重新发现圆内前三层并更新合成 |
| FR-009 | P1 | 兼容失败降级 | 某层无 DWM 表面时，不错误地把更深层画面覆盖到该层区域 |
| FR-010 | P1 | 可诊断性 | 探测模式输出层数、来源兼容性、平均/最慢帧耗时和恢复次数 |

## 6. 非功能需求

### 6.1 性能

- 目标轮询周期：16 ms；未来支持 8/16/33 ms 配置。
- 典型 180 px 半径、三层场景：平均更新耗时 < 20 ms，P95 < 33 ms。
- 单帧不得创建按 3px 分割的百级 DWM 缩略图；每层最多一个缩略图。
- 鼠标静止时不重复更新 DWM 属性或窗口位置。

### 6.2 稳定性

- 单个后台窗口关闭或重建时安全停止或重建场景。
- 不允许异常穿越 P/Invoke 回调边界。
- 正常恢复后目标窗口 region 类型和后台扩展样式与启用前一致。

### 6.3 安全与隐私

- `asInvoker`、`uiAccess=false`。
- 无网络、遥测、持久化、进程注入、远程线程和进程内存访问。
- 全局低级鼠标钩子只在透视会话期间存在，仅观察鼠标按下以完成 Z-order 约束；不阻断或改写事件。
- 未签名构建必须明确提示 SmartScreen/信誉风险；1.0 前需要 Authenticode 代码签名。

## 7. 交互规则

1. F8 按下时锁定鼠标所在的宿主顶层窗口。
2. 圆形实体 region 与视觉合成使用同一次鼠标坐标采样。
3. 合成器按宿主之后的顶层窗口顺序发现最多三层。
4. 上层窗口只遮挡自己占据的区域，空白处继续显示更深层。
5. 鼠标按下前识别实际目标；允许的目标被设置为非激活并移动到宿主正下方。
6. 受保护目标不注册 DWM、不改样式、不改 Z-order，向用户报告原因。

## 8. 兼容性与降级

完整矩阵见 [COMPATIBILITY.md](COMPATIBILITY.md)。标准 Win32、WinForms、WPF、普通 Chromium/Electron 和多数 DWM 窗口是首要支持对象。DRM 视频、独占全屏、DirectComposition/硬件 overlay、`WS_EX_NOREDIRECTIONBITMAP`、安全桌面、管理员权限不匹配和反作弊应用属于受限或不支持范围。

## 9. 发布与成熟度路线

- 0.7：单圆三层合成、安全排除、诊断、自动测试和产品文档。
- 0.8：托盘 UI、快捷键/半径配置、每应用规则、崩溃恢复守护进程、结构化日志。
- 0.9：安装包、自动更新、代码签名、Windows 10/11 与多 GPU beta 矩阵、无障碍检查。
- 1.0：公开稳定版；完成签名、崩溃恢复、兼容数据库、隐私/安全说明和支持流程。

## 10. 成功指标

- 受支持应用的启用成功率 ≥ 98%。
- 典型硬件移动帧 P95 ≤ 33 ms。
- 10,000 次启用/恢复循环无 region 或窗口样式残留。
- 公开 beta 中“误触发安全软件/反作弊”零确认事件；任何个案立即进入默认排除名单。
- 双圆不同步自动测试为零失败。
